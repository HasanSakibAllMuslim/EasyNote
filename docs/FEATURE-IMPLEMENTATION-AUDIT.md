# EasyNote feature implementation audit

**Method:** source inspection of this branch, not an interactive/functional QA run. The existing local installer was found stale relative to this source; no installer was launched or rebuilt.

| Feature | What the UI promises | What current source implements | Offline / account dependency | Assessment |
| --- | --- | --- | --- | --- |
| Cloud save | Metadata and onboarding text say work syncs automatically to the cloud. | `js/store.js` writes to IndexedDB and has no cloud sync code. | Local persistence works offline; no account/service connection exists. | **Not implemented; UI promise is false.** |
| Google sign-in | Login screen presents a Google sign-in action. | `googleSignIn()` in `js/store.js` resolves immediately. `onUser()` synthesizes one `Offline User`; no Firebase Auth flow is used by the active app. | No Google account or network required; no real authentication occurs. | **UI placeholder.** |
| Payment verification | Payment screens claim an SSLCommerz transaction is checked and a plan activated. | The UI opens configured SSLCommerz links externally. `validTxn()` always returns true and `verifyPayment()` always returns `{ ok: true }`; subscription/profile functions return local stub data. No server-side verification exists. | Visiting the payment site needs internet and any account/payment provider requirements. The app's “verification” succeeds locally even offline. | **Placeholder and release blocker for paid use.** Do not use it to collect payment or enforce entitlements. |
| Local/offline storage | App has offline/local note use; some UI also promises cloud backup. | IndexedDB stores notebooks, pages, and imported PDF bytes. `localStorage` stores selected preferences. The configured Electron origin is stable. Installer setting preserves user data on uninstall. | Works without internet in current desktop implementation. One synthetic local user/profile is used; this is not account authentication or multi-user separation within the same app profile. | **Implemented in source; persistence was not functionally exercised in this audit.** |
| PDF import | UI offers opening a local PDF. | File input accepts `application/pdf`; source uses locally bundled PDF.js and sets worker, CMaps, and standard-font paths to local resources. | User-selected files; no account/network needed in this source path. | **Implemented in source; exact local installer is stale and lacks the current worker/PDF-Lib asset set.** No current-branch runtime render test performed. |
| PDF rendering/navigation | Editor uses PDF pages as notebook pages and exposes page/zoom navigation. | `js/editor.js` requests and paints pages via PDF.js, with caches and local rendering assets. | Intended to work offline from local libraries. | **Implemented in source; not manually tested here.** |
| Board drawing | UI offers blank board backgrounds and editor tools. | Canvas editor implements pointer-based ink, highlighting, shapes, text, eraser, page operations, undo/redo, and stored page objects in `js/editor.js`. | Local, no account or internet needed. | **Implemented in source; not manually tested here.** |
| Save notebook | UI says notes are saved as users work. | `js/main.js` queues page/meta changes through `savePage`/`saveMeta`; `js/store.js` persists those records in IndexedDB. | Local and offline; data is tied to the local Electron profile/origin. | **Implemented in source; no persistence test run in this step.** |
| Export PDF | UI offers a PDF download/export. | `js/main.js` uses local PDF-Lib. It copies source pages when possible and paints the notebook content/annotations onto canvas PNGs before embedding; blank boards and some rotated-PDF paths are rasterized. | Local, offline; no account needed. | **Implemented in source; output was not generated/re-imported in this audit.** Some annotation content is rasterized in the exported PDF. |
| External links | Community and payment screens expose links. | Electron main process allows `http`/`https` links to open in the system browser and blocks in-app navigation. | Requires internet only when user opens the link. | **Implemented; destination-site behavior is outside this audit.** |

## Dormant Firebase files and remote resources

`js/firebase-config.js` imports Firebase 11.0.2 from `https://www.gstatic.com/...` and initializes a Firebase app if that module is loaded. Search found no import of this config in the active Electron entry-point graph. `libs/firebase-*.js` and `libs/css2` are included by broad packaging globs but have no active reference in this app source. Current app fonts, PDF.js, PDF worker, PDF-Lib, CMaps, and standard font files are bundled locally. This is source reference analysis, not a network trace of a built release.

## Important account and payment limitation

All launches receive the same synthetic `offline@local.pc` profile. The source compares that value with `ADMIN_EMAIL`, so the admin UI is not protected by real identity verification. Since the project has no live backend in this build, this does not grant access to a real remote database; it does mean the admin, payment, and account UI must not be represented as a functioning cloud service or secure entitlement system.
